하드웨어 인스턴싱 설계 근거
기존 렌더링 구조에서 인스턴싱을 적용할 수 없었던 두 가지 구조적 한계
한계 1
ConstantBuffer는 인스턴싱에
사용할 수 없다
DrawIndexedInstanced로 N개를 그려도 모든 인스턴스가 cbuffer의 동일한 world_matrix를 사용해 겹쳐서 렌더링
→ SV_InstanceID로 인덱싱 가능한 StructuredBuffer 필요
한계 2
Mesh::Render()는 인스턴스
개수를 알 수 없다
오브젝트마다 개별 호출되는 구조 Mesh는 씬에서 자신을 공유하는 오브젝트 수를 파악할 수 없음 → DrawIndexedInstanced 인스턴스 개수가 구조적으로 항상 1
→ Material이 batches_로 집계 후 RenderInstancing에 count 전달 필요
Before — Mesh::Render()
Mesh.cpp Before 
// 각 MeshComponent가 개별적으로 호출 → 인스턴스 개수 = 1로 고정
void Mesh::Render(
    ID3D12GraphicsCommandList* command_list,
    int material_index, FrameResource* curr_frame_resource)
{
    command_list->IASetVertexBuffers(0, ...);
    command_list->IASetIndexBuffer(&index_buffer_views_[material_index]);

    // Mesh는 자신을 공유하는 오브젝트 수를 알 수 없음
    command_list->DrawIndexedInstanced(
        indices_array_[material_index].size(),
        1,   // ← 항상 1 (인스턴스 개수를 받을 인터페이스 없음)
        0, 0, 0);
}
// 동일한 Mesh 오브젝트 100개 → 이 함수 100번 호출
After — Material::Render() + Mesh::RenderInstancing()
Material.cpp + Mesh.cpp After 
// Material: 같은 Mesh를 공유하는 컴포넌트 수를 batches_로 집계
for (const auto& [mesh, components] : batches_)
{
    auto instance_count         = components.size();         // 집계된 수
    auto instance_buffer_offset = components.front()->constant_buffer_index();
    mesh->RenderInstancing(cmd, sub_mesh_index,
        curr_frame_resource, instance_count, instance_buffer_offset);
}

// Mesh: Material에서 받은 instance_count를 DrawCall에 그대로 전달
void Mesh::RenderInstancing(..., int instance_count, int offset)
{
    command_list->DrawIndexedInstanced(
        indices_array_[material_index].size(),
        instance_count,   // ← Material에서 집계된 실제 인스턴스 수
        0, 0, 0);
}
핵심: Mesh::Render()는 호출마다 무조건 Draw(1)을 발행하므로, 같은 Mesh를 공유하는 오브젝트가 100개여도 100회 Draw Call이 발생한다. Material이 batches_로 집계한 instance_count를 RenderInstancing에 전달함으로써 1회 Draw Call로 전환된다.
